# E91 Entanglement-Based QKD

Phase 7 adds a compact E91 protocol path. Its purpose is to prove that the
package can model entanglement-based quantum communication without folding E91
into BB84 internals.

## Core API

```python
from qiskit_qkd import (
    E91Config,
    E91Protocol,
    ProtocolConfig,
    Scenario,
    SourceConfig,
)

scenario = Scenario(
    pulses=2_048,
    clock_rate_hz=1_000_000.0,
    seed=91,
    protocol=ProtocolConfig(name="e91"),
    e91=E91Config(),
    source=SourceConfig(kind="entangled_pair"),
)

result = E91Protocol().run(scenario)
```

`E91Config` stores:

- `bell_state`: currently `psi_minus` or `phi_plus`.
- `alice_angles_rad` and `bob_angles_rad`: measurement settings.
- `key_setting_pairs`: setting pairs used for sifted key extraction.
- `chsh_terms`: signed setting pairs used to compute CHSH `S`.
- `bob_key_bit_flip`: default true for the singlet anticorrelation key pair.
  Set it to false for `phi_plus`, whose same-basis outcomes are correlated
  rather than anticorrelated; keeping the flip there drives key QBER to 1.
- `chsh_estimation_enabled`: switch for Bell-test diagnostics.

`E91Protocol` has no eavesdropper models: it rejects scenarios whose
`eavesdropper.kind` is not `none`. Adversarial studies currently belong to the
BB84 path.

## Layering

E91 follows the same separation as BB84:

- Qiskit prepares the Bell state, applies the Bob-channel marker, coherent
  channel rotations, optional source-pair Pauli errors, and angular
  measurements.
- The event layer handles pair emission, Bob-arm channel survival, timing
  gates, detector efficiency, dark counts, background clicks, dead time, and
  afterpulses.
- The classical layer uses only public coincidence data, Alice/Bob settings,
  and detected bits to compute key QBER and CHSH correlations.
- Analysis helpers flatten Bell rows for plotting.

The first E91 model uses one explicit quantum channel arm toward Bob, matching
the existing BB84 link model. Alice is local to the source but still measured
through an independent detector instance built from `DetectorConfig`.

Channel optical background, including Raman crosstalk derived from the Bob-arm
channel, is applied only to Bob's detector. Alice still has detector dark
counts, dead time, and afterpulsing, but she does not receive Bob's
distance-dependent channel background in this co-located-source model.

Coincidences require Bob's signal to remain in Alice's emitted time slot:
`assigned_slot == time_slot`. If `slot_assignment_policy="nearest"` moves a
signal into a neighboring Bob gate, that signal is not counted as an E91
coincidence for the original Alice slot. It can still be traced through timing
metadata as a simulator diagnostic.

## Source Imperfection

For E91, `SourceConfig.preparation_error_probability` is interpreted as a
Bell-pair preparation imperfection. When sampled, the backend applies one
random Pauli error (`X`, `Y`, or `Z`) on Bob's qubit before channel propagation.
This keeps the model simple, tangible, and inspectable in circuit metadata.

## Quantum Channel Noise

Coherent polarization misalignment uses the existing channel rotation fields:

```text
channel.polarization_rotation_y_rad
channel.polarization_rotation_z_rad
```

Those rotations are applied on Bob's qubit after the channel marker. Aer
depolarizing, phase-damping, and readout errors work through
`AerNoiseModelAdapter` exactly as in BB84: configure the scenario, build the
adapter, and pass its `noise_model` to `QiskitSamplerBackend`.

Photon loss, no-clicks, detector efficiency, timing gates, dark counts,
background light, dead time, and afterpulsing stay outside Aer.

Polarization-dependent loss is intentionally not applied as a classical
event-layer filter for E91 entangled states. In BB84, Alice's prepared
polarization is known before channel sampling, so PDL can be sampled
classically. In E91, Bob's photon is entangled and its polarization is not a
pre-existing classical label before measurement. A rigorous E91 PDL model would
need a quantum channel acting on Bob's qubit, such as a non-unitary loss model,
rather than the BB84 event-layer PDL approximation.

## Result Fields

`SimulationResult.metrics.chsh_s` stores the CHSH value when all configured
terms have coincidences. `SimulationResult.bell` stores:

```text
protocol
bell_state
chsh_enabled
chsh_s
bell_violation
key_setting_pairs
chsh_terms
setting_rows
```

Each setting row contains attempts, emitted pairs, Bob-arm transmissions,
coincidences, same/different bit counts, correlation, and whether the row is
used for key or CHSH.

`SimulationResult.classical["secret_rate_model"]` is marked as
`pedagogical_bb84_asymptotic_qber_fraction`. The key-rate number is therefore a
didactic QBER-based comparison metric, not a device-independent finite-key
security bound.

For plots:

```python
from qiskit_qkd import bell_rows_from_result

rows = bell_rows_from_result(result)
```

## Boundary

This is an educational E91/CHSH simulator. It is not a loophole-free Bell test,
not a device-independent finite-key proof, and not a full SPDC multi-pair
source model. Future work can add dual-arm channel configuration, E91-specific
quantum PDL/loss channels, finite-key confidence intervals,
detector-efficiency mismatch attacks, and entanglement swapping.
